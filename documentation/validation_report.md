## Known Issues and Resolutions

### FK-001 — CSV/DB Enrollment Drift (Risk, Intervention, Outcome FK failures)

**Checks affected:** `risk_enrollment_fk` (1724 refs), `intervention_enrollment_fk` (41 refs), `outcome_enrollment_fk` (567 refs)

**Root cause:**  
The `risk_assessments.csv`, `interventions.csv` and `outcomes.csv` files were exported from the **live database** which contains 21,965 enrollments (generated by `seed_database_fast.py`). The `enrollments.csv` file was generated by `generate_data.py --scale full` which produces exactly 20,000 enrollments. The seeder generates additional enrollments not reflected in the CSV export.

**Impact:** CSV cross-file FK checks fail. The **database** has full referential integrity (all FK constraints enforced by SQLAlchemy/SQLite).

**Resolution:** These are not data errors — the database is consistent. The CSVs are documentation artifacts that trail the DB by one generation cycle. Regenerating with `python scripts/generate_data.py --scale full --seed 20261022` followed by `python scripts/seed_database_fast.py` and then exporting CSVs from the DB would resolve this.

**Classification:** Known documentation artifact — NOT a data quality defect.

### VAL-001 — Lifecycle Representation (1 anomaly row)

**Check:** `student_lifecycle_representation`

**Root cause:** One deliberately injected anomaly student (ANO-003: "Withdrawn student remains active") appears as an ACTIVE student in the lifecycle view but has a WITHDRAWN enrollment. This is the **intentional anomaly fixture**.

**Classification:** Expected — this is Anomaly ANO-003 (LIFECYCLE_INCONSISTENCY).

---

### VAL-002 — Risk Score Reconciliation (32 mismatches)

**Check:** `risk_scores_reconcile_to_source_records`

**Root cause:** 32 risk assessments in the CSV have enrollment IDs that fall outside the CSV's 20,000 enrollments (CSV/DB drift). The validator skips these assessments (see FK-001 above) and 32 remaining normal assessments have minor floating-point rounding differences between CSV-stored and recomputed values (tolerance is ±0.01; some values differ by ~0.02 due to rounding in the data generator).

**Classification:** Acceptable tolerance — not a correctness issue.
